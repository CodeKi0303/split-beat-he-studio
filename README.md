# Split-Beat HE Studio

[studio.codekilab.com](https://studio.codekilab.com/)에서 Chrome으로 키보드를 연결합니다. 물리 키를 골라 매핑하고, Hall 키를 보정한 뒤 작동점·Rapid Trigger·데드존을 설정합니다. 센서와 리듬 진단도 이 화면에서 확인할 수 있습니다.

## 시작하기

1. PC를 왼쪽 키보드 뒤쪽 바깥(노브 쪽) 포트에 연결하고, 두 안쪽 포트끼리 e-marker가 없는 60W 미만 USB-C ↔ USB-C 데이터 케이블로 잇습니다. 포트 그림은 [사용 설명서](https://docs.codekilab.com/#start)에 있습니다.
2. **키보드 연결**을 눌러 장치를 선택합니다. 보정하지 않은 Hall 키가 있으면 캘리브레이션 화면이 자동으로 열리고, 메뉴에 남은 키 수가 표시됩니다. 키를 놓은 값과 끝까지 누른 값을 수집한 다음 적용합니다.
3. 매핑과 작동점을 설정하고 **키보드에 저장**합니다. 펌웨어 0.4.0 이상에서는 사이드바의 프로필 1–4로 작동점·RT·매핑을 따로 둘 수 있습니다(보정은 공통).
4. **펌웨어** 탭에서 정식 릴리스를 불러오고 **양쪽 버전 확인** → 동의 → **좌우 업데이트** 순으로 진행합니다. Studio 연결은 이 탭이 잠시 넘겨받고, 끝나면 **키보드 연결**로 다시 연결합니다. 오른쪽은 왼쪽 USB를 통해 갱신합니다.

[사용 설명서](https://docs.codekilab.com/) · [하드웨어 주문](https://github.com/CodeKi0303/split-beat-he-hardware) · [펌웨어 릴리스](https://github.com/CodeKi0303/split-beat-he-firmware/releases) · [수평 휠](https://github.com/CodeKi0303/split-beat-he-wheel)

## 고정 해제 지점

펌웨어 0.5.0 이상에서 **작동점 · RT** 탭의 Hall 키를 선택하고 **래피드 트리거**를 끄면 **고정 해제 지점**이 나타납니다. 예를 들어 작동 1.00 mm, 해제 0.70 mm이면 누른 뒤 0.85 mm까지 돌아와도 입력을 유지하고, 0.70 mm에서 해제합니다. **작동점 따르기**를 누르면 작동점보다 얕아질 때 해제하는 기본 동작으로 돌아갑니다. 여러 키를 선택하면 같은 mm 값을 각 키의 스트로크에 맞게 적용합니다.

## 자동 맞춤

보정된 Hall 키를 선택하고 **리듬 · RT 측정 → 자동 맞춤**에서 손 떼기, 손가락 얹기, 반복 입력, 길게 누르기를 측정합니다. 균형·연타·유지 중 선호하는 방향에 맞춰 작동점과 RT 후보를 비교합니다. 추천값을 해당 키에 적용한 뒤 다시 측정해 확인하고, **키보드에 저장**으로 보관합니다.

추천은 브라우저가 받은 센서 기록을 바탕으로 합니다. 샘플 사이의 짧은 변화와 실제 게임 판정은 추가 확인이 필요합니다. [MCP 플러그인](https://github.com/CodeKi0303/split-beat-he-plugin)에서도 단계별 안내와 측정을 진행할 수 있습니다.

## 키 출력 유지

Studio는 **출력 끄기**를 눌렀을 때만 키 출력을 끕니다. 연결 종료로는 출력이 바뀌지 않습니다. 설정 적용·보정·ADC 변경·프로필 가져오기 때는 펌웨어가 안전을 위해 출력을 잠시 끄지만, 작업이 끝나면 Studio가 작업 전 상태로 다시 켭니다. 리듬·자동 맞춤·간섭 측정 중에는 측정용으로 꺼 두고, 측정이 끝나면 되돌립니다.

출력 켜기가 `BUSY`로 거부되면 오른쪽 보드 연결이 한 번 끊긴 뒤 펌웨어가 좌우 ADC 설정 확인을 기다리는 상태입니다. **센서 진단/설정**의 ADC 설정에서 **좌우에 적용**을 한 번 누른 뒤 다시 켜세요.

## 키 간 간섭 비교

**센서 진단/설정 → 키 간 영향 비교 측정**에서 기준을 수집하고 선택한 키 하나를 누른 채 다시 수집합니다. 다른 키를 선택해 반복하면 물리 키별 행에 양쪽 센서의 평균 변화가 쌓입니다. C86은 센서 중심 간 21 mm 이내의 이웃을 표시하며 지원 버전에서는 좌우 정식 펌웨어의 ADC 변환 순서도 표시합니다. **비교표 내보내기**로 표본 수·ADC 설정·최근 측정값을 JSON에 저장해 다른 기판과 비교할 수 있습니다.

## ADC → 거리 곡선 그리기

보정된 C86에서는 같은 그래프의 **WISH 미리보기**로 센서값을 Owlab Ti HE의 33점 자속 모델에 대입한 거리를 확인할 수 있습니다. 펌웨어 v0.6.0 이상에서 **WISH 방식 · Owlab Ti HE → 곡선 적용**을 선택하면 키보드도 이 곡선으로 판정합니다. 선택한 키의 보정 끝점과 커스텀 표는 보존되고, 그래프에는 평균 ADC를 환산한 거리와 펌웨어가 보고한 거리가 함께 표시됩니다. 모델의 기준 트래블은 3.4 mm이며, 이미 브라우저에 저장한 이동거리가 있으면 그 길이에 비례해 표시됩니다.

**센서 진단/설정**의 **ADC → 거리 곡선**에서 선택한 키의 ADC 신호(보정 범위 %·쉼 위 코드)와 판정 거리(mm)를 직선, Owlab Ti 근사, 커스텀 곡선으로 함께 봅니다. 작동점과 현재 ADC 위치도 표시합니다. 그래프 위를 마우스로 끌면 커스텀 곡선을 그리며, 깊어질수록 거리가 줄어들지 않게 자동으로 맞춥니다. 곡선과 적용 범위를 고른 뒤 **곡선 적용**을 누르면 키보드 RAM에 반영되고, 유지하려면 **키보드에 저장**을 누릅니다.

커스텀 곡선은 **펌웨어 v0.3.46 이상**이 필요하며 키보드 전체가 함께 쓰는 표 하나입니다. 커스텀 곡선을 쓰는 키가 있으면 Studio v1.0.12 이하와 MCP 플러그인 v0.1.5 이하는 설정을 읽지 못합니다. 프로필 JSON에는 커스텀 표가 포함되지 않습니다.

## 0.001 mm 설정

**작동점 · RT**의 작동 지점, 눌림·복귀 RT, 상·하단 데드존을 0.001 mm 간격으로 입력합니다. 입력값 그대로 저장하려면 **펌웨어 v0.3.43 이상**이 필요합니다. 이전 펌웨어에서는 총 이동거리의 1/1000 단위(3.4 mm 기준 약 0.0034 mm)로 반올림해 적용합니다. 입력 간격이 센서 정밀도를 뜻하지는 않으며, 실제 판정은 ADC 1단계 단위로 움직입니다. 이전에 내보낸 프로필 JSON은 그대로 가져올 수 있습니다.

## 개발과 배포

```sh
python -m http.server 8877 --bind 127.0.0.1 --directory web
node tests/web_firmware_update_test.mjs
```

Chrome에서 `http://127.0.0.1:8877/`을 엽니다. 운영 산출물에는 장치 시뮬레이터를 포함하지 않습니다.

Studio의 정식 릴리스 또는 펌웨어 저장소의 배포 요청으로 Actions가 실행됩니다. 최신 정식 Studio 릴리스의 웹 코드와 최신 정식 C86 좌우 앱을 검증하고 한 배포에 담습니다. 운영 대상은 Cloudflare Pages `split-studio`와 `studio.codekilab.com`입니다. GitHub Actions의 `CLOUDFLARE_ACCOUNT_ID` 변수와 `CLOUDFLARE_API_TOKEN` Secret을 설정합니다.
